# Personal Pi 1.x alignment (#727)

This cleanup applies to the shared Mac/Omarchy personal profile. Work agent-kit,
notes/Telegram, credentials, and sessions retain their separate ownership.

## Baseline and startup notice

Both hosts ran Pi **1.1.0** with personal `PI_CODING_AGENT_DIR=~/.config/pi`.
The Mac session inherited an npx `pi` binary ahead of the Nix wrapper; the managed
launcher itself remains `/etc/profiles/per-user/john.allen/bin/pi`. Omarchy uses
`~/.local/bin/pi`. Fresh managed launches follow upstream through Nix's npx
wrapper; an already-running agent retains its original runtime/profile.

Personal loaded `pi-headroom` 0.1.0, `pi-mcp-adapter` 5.1.0,
`pi-prompt-template-model` 0.12.3, and `pi-web-search` 1.7.0. Native MCP was disabled
with `extensions = ["-builtin:mcp"]`. The native package manager reported exactly
one available package update: `npm:pi-mcp-adapter` (npm latest: 5.2.0).

The notice is generated by **Pi itself**, not an adapter-specific updater:
`checkForPackageUpdates()` → `DefaultPackageManager.checkForAvailableUpdates()` →
`showPackageUpdateNotification()` in Pi's interactive mode. Its text is:

```text
Package Updates Available
Package updates are available. Run pi update --extensions
Packages:
- pi-mcp-adapter
```

`quietStartup` and telemetry preferences do not disable those checks. The adapter
notice disappears because that package is no longer configured, not because
updates or warnings are hidden. Native update checks remain enabled. Package
refresh stays owned by the existing `harness-refresh` worker.

## Decisions

| Resource | Decision and reason |
| --- | --- |
| Personal `pi-mcp-adapter` | **Remove**. Native streamable HTTP/stdio, OAuth, connection management, permissions hooks, deferred discovery, codemode, and bounded output cover the configured services. No demonstrated need for adapter-specific namespace proxies, SSE, MCP Apps, or dynamic URL installation in this personal setup. |
| Native MCP | **Enable**. Home Manager owns `~/.config/pi/mcp.json`; default codemode exposure avoids declaring every server tool. Use native `/mcp`, `tool_search`, and codemode discovery rather than the adapter's `mcp({...})` gateway. |
| Personal `SYSTEM.md` | **Replace** with `APPEND_SYSTEM.md`. Four personal instructions must not replace Pi's entire native system prompt. Activation removes only the exact retired managed content (ignoring whitespace); a differing user override is preserved with a warning. Work `SYSTEM.md` is unchanged. |
| Explicit personal `hideThinkingBlock=false` | **Remove**; native default is already false. |

| `pi-web-search` | **Retain**. Provider-native web search/URL analysis is not one of Pi's built-in coding tools or MCP transport features. |
| `pi-headroom` | **Retain**. Its managed compression proxy handles inference context/results; native MCP codemode instead controls discovery/tool exposure. Existing Omarchy runtime-library wiring is still needed. |
| `context-inspection` | **Retain, adapt**. Native `/session` supplies usage but not this extension's detailed native/extension schema budget. Native MCP tools now come from the actual registry, not stale adapter cache files; native codemode/tool-search costs are identified as shared gateways. |

| Explicit-profile Node shim edge case | **Separate #715**. Noninteractive personal verification prepends Nix Node to avoid re-entering work directory context. No work-profile takeover in this cleanup. |

| Dormant global package copies | **Leave unregistered**. Native resource discovery does not load them; ownership of global installations is not inferred from personal profile state. |
| Rose Pine, model/thinking, padding, fullscreen, quiet header, telemetry opt-out, terminal progress, cache notices | **Retain deliberate preferences**. Their settings remain supported by Pi 1.x. |

The unused historical adapter package lock is removed. The Pi integration skill
now describes profile-local npm installs, current refresh/deployment commands,
and native MCP rather than the retired global-install/direct-rebuild recipe.

## MCP compatibility and authentication

Configured servers remain profile/host appropriate:

- Mac Headroom: stdio MCP with `--proxy-url http://127.0.0.1:8787`; omitted on
  Omarchy as before (the inference-compression extension remains shared).
- Doppler: Mac stdio Bash wrapper resolves the existing `doppler-work` Keychain
  credential; Omarchy inherits `${DOPPLER_TOKEN}` through stdio `npx`.
- MotherDuck: stdio `uvx`, existing `--read-write` policy preserved. Smoke query is
  read-only `SELECT 1`, not a database mutation.
- Cloudflare: **work-only** streamable HTTP. John clarified that personal Pi does
  not use it; the follow-up removed its personal Mac/Omarchy declaration rather
  than requesting unnecessary personal authorization. Work configuration is unchanged.

Before migration, native MCP connected Mac Headroom, Doppler (128 tools), and
MotherDuck (4 tools). Cloudflare required sign-in **under both implementations**:
the adapter store had a client registration but no token. No authorized token
needed conversion or transfer. Existing adapter keychain entries/caches remain
untouched; native OAuth uses the selected profile's `mcp-auth.json` with restrictive
file permissions. Native OAuth's file storage differs from the adapter's keychain
backend; credentials are never placed in Nix or synchronized between hosts.

Omarchy's noninteractive personal environment did not have a Doppler token before
this task. Profile-specific service-account authorizations remain in **#694**;
missing approvals for intended services are not concealed. Removing personal
Cloudflare is a profile-scope correction, not warning suppression. Native
synthetic tests exercise authenticated HTTP calls and server-name/URL isolation
without requiring browser approval, secret output, or paid model calls.

Native MCP sends tool calls through Pi's permission/event pipeline, including
codemode calls; destructive annotations remain available. Codemode scripts can
filter full results before returning them, while direct model-facing results have
a native bounded-output/file fallback. There is no adapter gateway/schema overhead.
Persistent MCP edits belong in Nix: native `/mcp` edits cannot rewrite a store link.

## Follow-up: proxied Codex quota footer

The retained Mac footer recognized only `openai-codex`. After the separate
central-proxy rollout selected `subscription-codex`, it incorrectly fell back to
`usage: $0.000 session`. The footer now queries the selected gateway account
through `subscription-proxy codex-usage personal --base-url <selected-model-url>`.
The helper uses the official panel's read-only quota request with a server-side
`$TOKEN$` placeholder; upstream OAuth tokens are never downloaded. Output is
allowlisted quota fields only. Wrong gateways, missing/ambiguous pooled accounts,
and request failures display unavailable quota, never local-account fallback.
Polling is bounded and throttled, and caches are scoped to provider/profile/URL.

Display actual returned windows and reset times: the current personal `prolite`
plan returns a 7-day window only. Do not invent a missing 5-hour percentage.
Native Codex usage still works. Omarchy's cross-profile footer exclusion remains
unchanged; its shared quota helper is deployed and independently verified.

```bash
# Mac: actual managed factory/rendering plus a read-only gateway quota check
PI_CODING_AGENT_DIR="$HOME/.config/pi" node tests/pi-usage-footer.mjs "$runtime" --installed --live
```

Run `tests/subscription-proxy.py` with the managed helper's Nix Python (PyYAML).
Use `/reload` or a new personal Pi session after activation for the footer and
MCP removal. No package refresh or Claude restart is needed for this follow-up.
